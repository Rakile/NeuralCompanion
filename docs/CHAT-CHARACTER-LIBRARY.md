# Chat Character Library

Open **Settings → Tools → Chat characters** in a matching native phone app connected to NC. The desktop owns the character library, voices, and generation services. This library is separate from the main Persona editor and the moderated Local/Discord room. See [Main Chat Remote](addons/main_chat_remote.md) for connection setup and [Voice Studio](addons/voice_studio.md) for voice-generation prerequisites.

## Use

1. Connect the phone by LAN or Internet and open Chat characters.
2. Turn on **Character voices** to use structured dialogue routing (default OFF, including existing conversations after this update). Separately turn on **Allow new characters** to discover additional speakers. It is off for every new conversation. **Maximum characters**, directly below the toggle, defaults to 6 and supports 1–20. The limit is enforced by the desktop per conversation; extra speakers use the narrator, and lowering it never deletes existing cards. Loading a saved conversation restores its cast and setting.
3. Continue a story. Unknown named speakers appear as candidate suggestions. Tap **Add to library** to create a character card. Generic roles are not automatically added. Narrator playback continues, and assigned voices apply to the next reply.
4. Tap a card to edit its name, role, description, optional character and interaction instructions, voice description, sample dialogue and portrait prompt. Long-press a library card for **Remove**, **Add to chat**, and **Remove from chat**. Remove deletes the card after confirmation. Remove from chat takes it out of the current cast but keeps its voice, portrait, and edits in All conversations; Add to chat brings a saved card back. Save is explicit. Stale edits are rejected rather than replacing newer desktop changes. New cards start with empty instructions; background enrichment may propose them from the story excerpt without overwriting your edits. They enter only the opt-in Character voices prompt and do not replace the main persona's system prompt.
5. Tap **Use: [name]** to assign an existing saved voice, or generate candidates with a configured Voice Studio provider. The assigned name is shown on the card. Newly generated candidates receive names such as **Kaelith — Voice 1**, are saved as WAV files in NC’s `voices` folder with shared Voice Studio metadata, and remain unassigned until you choose one. Preview is available only while the reply is idle and Live Mode is off. Choose **Use voice** to assign a candidate. Generation never changes the desktop Voice Studio draft or the global chat voice.
6. Generate a portrait with the configured Visual Reply provider, review it and choose **Use portrait**. The portrait request uses the desktop image-prompt refiner when available, positive single-subject framing, and a provider negative prompt for ComfyUI's bubble/text exclusions. This does not change the current persona or current Visual Reply.
7. **Copy to NC Personas** creates an independent standard persona without activating it. The copy includes a standalone system prompt naming the character, its known role and description, its exact saved interaction instructions, and conversation guidance. The desktop prompt editor and Revert defaults start with that prompt; the assigned voice and portrait are retained. A newly discovered character with no description yet still gets a usable identity prompt without inventing a biography. Repeating the operation returns the original copy and preserves later edits. Later character edits do not change that copy.

Distinct character playback requires Backend HQ and a supported voice-reference engine (the existing Chatterbox/Multilingual/PocketTTS routes). Phone Native keeps its existing narrator voice. Multi Persona Roleplay must be loaded to own this library, but its roleplay mode need not be enabled. Voice Studio must be loaded for voice generation. Portrait generation uses the existing configured Visual Reply provider; provider credentials remain on the desktop.

## Dialogue and playback rules

Character voices OFF uses the original normal generation and single-voice speech route, regardless of the discovery setting. Character voices ON requests small structured speaker records. Only dialogue and first-person thoughts use assigned voices; narration, unknown speakers and missing references use the main voice. Allow new characters OFF still permits existing assigned voices but suppresses candidates. Disabling either setting preserves existing cards.

A request-scoped voice context is frozen when generation is prepared. Edits apply to the next reply. A bounded incremental JSON framer accepts complete records (including pretty-printed objects), validates content and resolves IDs against that snapshot. NC assigns segment sequence numbers. The same accepted text supplies chat history and typed VoiceSegments for the existing queue. Incomplete or malformed envelopes are never spoken. Readable plain-prose fallback uses the main voice. A provider failure after speech admission does not replay the response.

The feature reuses synthesis, phone capture/native suppression, cancellation, ordered playback, WebRTC/Opus, buffering and reconnect ownership. No additional classifier request is made per quote. Portrait and voice creation continue using their existing jobs. Optional card enrichment runs only after a candidate is accepted.

## Storage and transport

MPRC owns a separate `chat_characters.json`, with stable conversation IDs saved in chat-memory exports. Legacy memories get a fresh cast scope on import. Voice Studio owns durable candidate job receipts; portraits have equivalent managed candidate storage. Jobs are bounded and revision checked. Uncertain provider outcomes are shown as Unknown and are never automatically resubmitted. Cancel discards late results; it cannot undo a provider request already accepted or guarantee a billing refund.

The gateway advertises `features.chat_characters_version = 1`. Routes are authenticated and allowlisted under `/api/chat-characters`; LAN and Internet use the same desktop dispatcher. Mutations carry `expected_revision` and `operation_id`. Generation creates a job; assignment is a separate action. Media URLs contain opaque IDs. Portraits use the existing phone cache; audio previews remain temporary. Story content continues over the peer data channel, never relay signaling.
